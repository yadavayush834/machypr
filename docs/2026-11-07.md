# Desktop changes — 7 November 2026

The user templates include Tahoe GTK themes/icons and WhiteSur fallback, optional glass settings, local Dashboard notes, updated appearance palettes, developer application pins/class aliases, Alt+Tab cycling, title-bar drag refinements, the lock screen, display activation on resume/lid open, startup environment import and deferred desktop shortcut creation. Application launcher IPC keeps one hidden grid ready; application-list changes invalidate its contents. New user services include optional desktop health reporting and delayed update notifications, plus launcher readiness and app-file caching. No notes, browser profiles, credentials, state reports, logs, screenshots or backups are included.

## User services

`arch-start` starts `macos-launchpad.service`, `macos-app-cache.timer` and the existing update notification timer after importing the compositor environment. The cache reads at most 768 MiB at idle I/O priority and stops below 3 GiB available memory. It does not start applications. The launcher releases keyboard focus before launching an application and stays hidden afterward.

To enable the optional non-invasive health report: `systemctl --user enable --now mac-os-health.timer`. It reports configuration/IPC failures; it never kills an active desktop. Update notifications count repository and Flatpak updates without installing them.

## Optional laptop system settings

`system/` is deliberately outside the user-template tree and is not installed automatically. The logind drop-in suspends on lid close on AC, battery and while docked. Install it only if that docked behavior is wanted.

`~/.local/bin/configure-fast-wake` requests administrator authentication, selects s2idle and writes a persistent systemd sleep drop-in. Check that `/sys/power/mem_sleep` lists s2idle first. It generally favors resume latency over sleeping battery life; test lid wake on the target hardware. The `--undo` option removes this helper's drop-in and selects deep sleep on machines supporting it. `system/etc/systemd/sleep.conf.d/90-fast-wake.conf` records the corresponding setting.

`examples/laptop/disable-f11.lua` and `disable-f12.lua` preserve workarounds for faulty keys on the development laptop. They suppress those keys on every keyboard and must be opted into manually. Healthy keyboards should leave them disabled.

## Optional guarded sign-in

The two desktop files under `system/usr/share/wayland-sessions/` are templates for SDDM. Replace `@HOME@` with the intended user's absolute home directory before installing them as root. The session supervisor preflights the configuration, waits up to 45 seconds for a display and makes at most one plugin-free recovery attempt. Recovery does not restore unsaved application state.

The supervisor disables optional title-bar plugins unless a matching trusted SHA-256 baseline exists at `~/.local/share/startup-tuning/plugin-baseline.json`. The existing standard installer/session remains available. The normal and recovery templates are portable; no machine-specific boot partitions, EFI entries or disk UUIDs are applied. The development laptop also received a mac-os boot-menu label, a three-second visible GRUB menu and a matching SDDM session selection; these firmware and disk-specific operations remain local.

## Verification

The full portable install/restore and desktop logic checks run with `bash scripts/check.sh`. The session supervisor tests cover clean logout, invalid configuration, crash recovery, bounded retries, display readiness and startup timeout. Live checks on the development laptop exercised launcher show/hide, search-to-application launch, focus release, native configuration validation and cache residency. Repeat launcher opens measured about 70–75 ms versus 600–770 ms before; no application-wide cold-start speedup is claimed.

## Keyboard focus and Codex login follow-up

The desktop icon surface now starts without keyboard interactivity. On Hyprland 0.57, the previous on-demand layer could take focus when the pointer crossed the desktop, even with click-to-focus enabled. Returning the pointer to an application then left typing directed at the desktop until the application was clicked again. Icons request keyboard focus only after a completed click or drag and release it when the pointer leaves or focus moves away.

Live verification reproduced focus loss before the change and retained application focus afterward using the same application → desktop → application pointer movement. The existing icon monitoring/dragging check is available as `python scripts/test-desktop-icons.py` in a running desktop session.

For Codex CLI, [examples/codex/config.toml](../examples/codex/config.toml) records the explicit file credential-storage setting applied locally. Merge that top-level setting into an existing configuration before any table headers; do not replace an existing configuration with the example. It is optional and is not applied by the desktop installer. Authentication tokens, account details and the local Codex configuration are excluded from this change. See the [official authentication documentation](https://learn.chatgpt.com/docs/auth).

Normal `/quit` and Ctrl+D exit checks preserved the saved login. Historical logs contained explicit logout/revocation requests, whose trigger was not reproduced; persistent storage alone is not a confirmed fix for those requests.
