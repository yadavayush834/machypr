# Desktop changes — 7 November 2026

The user templates include Tahoe GTK themes/icons and WhiteSur fallback, optional glass settings, local Dashboard notes, updated appearance palettes, developer application pins/class aliases, Alt+Tab cycling, title-bar drag refinements, the lock screen, display activation on resume, startup environment import and deferred desktop shortcut creation. Application launcher IPC keeps one hidden grid ready; application-list changes invalidate its contents. New user services include optional desktop health reporting and delayed update notifications, plus launcher readiness and app-file caching. No notes, browser profiles, credentials, state reports, logs, screenshots or backups are included.

## User services

`arch-start` starts `macos-launchpad.service`, `macos-app-cache.timer` and the existing update notification timer after importing the compositor environment. The cache reads at most 128 MiB at idle I/O priority after five minutes on AC, defers under PSI/thermal pressure and stops below 4 GiB available memory. It does not start applications. The launcher releases keyboard focus before launching an application and stays hidden afterward.

To enable the optional non-invasive health report: `systemctl --user enable --now mac-os-health.timer`. It reports configuration/IPC failures; it never kills an active desktop. Update notifications count repository and Flatpak updates without installing them.

## Optional guarded sign-in

The two desktop files under `system/usr/share/wayland-sessions/` are templates for SDDM. Replace `@HOME@` with the intended user's absolute home directory before installing them as root. The session supervisor preflights the configuration, waits up to 45 seconds for a display and makes at most one plugin-free recovery attempt. Recovery does not restore unsaved application state.

The supervisor disables optional title-bar plugins unless a matching trusted SHA-256 baseline exists at `~/.local/share/startup-tuning/plugin-baseline.json`. The existing standard installer/session remains available. The normal and recovery templates are portable; no machine-specific boot partitions, EFI entries or disk UUIDs are applied.

## Verification

The full portable install/restore and desktop logic checks run with `bash scripts/check.sh`. The session supervisor tests cover clean logout, invalid configuration, crash recovery, bounded retries, display readiness and startup timeout. Optional live checks exercise launcher focus and configuration validation; performance depends on the host hardware.

## Keyboard focus

The desktop icon surface now starts without keyboard interactivity. On Hyprland 0.57, the previous on-demand layer could take focus when the pointer crossed the desktop, even with click-to-focus enabled. Returning the pointer to an application then left typing directed at the desktop until the application was clicked again. Icons request keyboard focus only after a completed click or drag and release it when the pointer leaves or focus moves away.

Live verification reproduced focus loss before the change and retained application focus afterward using the same application → desktop → application pointer movement. The existing icon monitoring/dragging check is available as `python scripts/test-desktop-icons.py` in a running desktop session.

The Apple menu, Dock, Spotlight and wallpaper picker open the app. The [feature/backend guide](SYSTEM-SETTINGS.md) documents working controls, optional Linux tools, Apple-only limitations, persistence, wallpaper provenance and validation commands.

Added a pinned native HyprGlass build, actual compositor refraction across normal app windows and selected shell panels, a truthful renderer-status command and fullscreen exclusion. Added full-screen floating-window movement constraints and monitor-relative initial/maximum sizes. [Implementation, limits and live regressions](REFRACTIVE-GLASS.md) distinguish real shader rendering from fallback styling and document the application-opacity compromise.

Added focus-aware reversible CPU weights, independent desktop launch scopes, pressure/temperature-aware background warmup, low-priority background jobs. [System performance documentation](SYSTEM-PERFORMANCE.md) describes scheduling, rollback and hardware limits. Animation settings are unchanged.
